        16 bugs, one storefront

        This is the Agentic Personas storefront from the ECI interview. It shipped with 16 hidden bugs. This tutorial walks through each one on the real app: what a user would have seen, how we found it, and how it was fixed.

        • Next / Back or the arrow keys move between steps.
        • API bugs started in the server. Their effect is shown on the page where a user would feel it.
        • WEB bugs live in the browser app.
        • The purple border is the LHI Spotlight on the affected element.
        • Two build-breaking bugs have no UI, so they show the real build error instead.

        API-0

        Nothing builds: shared package fails to compile

        The whole project would not build, so nothing else could even be tested. We stopped the compiler from picking up an unrelated type package.

        terminal · before the fix
        $ pnpm build
> @acme/shared build
> tsc

error TS2688: Cannot find type definition file for 'testing-library__jest-dom'.

BUILD_EXIT=2

        No screenshot is possible: the app would not build, so there was no UI to show. This panel is the real build error.

        How it showed up

        error TS2688: Cannot find type definition file for 'testing-library__jest-dom'. (findings/baseline-build.log, BUILD_EXIT=2)

        How we found it

        First command run on the clone: pnpm build. It stopped at @acme/shared.

        What the fix was

        tsc auto-includes every @types package it can see in ancestor node_modules. A stub for testing-library__jest-dom had no types, so the compiler failed on a package the code never uses. Shared needs no ambient types, so the fix is to say so explicitly (types: []) instead of installing a dependency to satisfy a file we do not import.

        Where in codepackages/shared/tsconfig.json (and apps/api/tsconfig.json)
        before compiler auto-included every stray @types package
        after "types": [] so only declared types are used

        API-1

        Price filter returned the wrong items

        Asking for personas costing at least $80 also returned cheaper ones.

        How it showed up

        GET /personas?minPrice=80 returned items at or below the minimum before the fix; after, only items from p-002 upward.

        How we found it

        Read the personas route and its db query while sweeping API behaviour.

        What the fix was

        A filter named minPrice must keep items at or above the value. The comparison used <= instead of >=. One character, but it silently inverts the feature.

        Where in codeapps/api/src/db.ts:~365
        before price <= minPrice
        after price >= minPrice
        commit 477e285
        API-2

        Login response was missing the username

        After signing in, the app did not receive the user's name, which the shared contract requires.

        How it showed up

        POST /auth/login returned a user without username. After the fix it returns user.username (tester in the smoke run).

        How we found it

        Compared the login handler's response object with the AuthResponse schema in packages/shared.

        What the fix was

        The shared Zod schema is the contract between web and API. The handler built the user object by hand and left one field out. Fix at the source, not by loosening the schema.

        Where in codeapps/api/src/routes/auth.ts:~119
        before user = { id, email }
        after user = { id, email, username }
        commit a2de6be
        API-3

        Browser could not delete cart or favorite items

        Removing something from the cart or favorites failed in the browser even though the API itself worked.

        How it showed up

        The allowed-methods list did not include DELETE, so the browser blocked the preflight request.

        How we found it

        Read the CORS configuration in the server entry file.

        What the fix was

        Direct curl calls succeed because CORS is only enforced by browsers. That is why this bug hides from API-only testing. Add DELETE to the allowed methods.

        Where in codeapps/api/src/index.ts:15
        before methods: [GET, POST, PUT]
        after methods: [GET, POST, PUT, DELETE]
        commit 7bd9759
        API-4

        Anyone could delete someone else's cart item

        A signed-in user could remove another user's cart item. This is a security hole.

        How it showed up

        DELETE skipped the item.userId === userId check that the PUT route has.

        How we found it

        Compared DELETE /cart/:itemId with PUT /cart/:itemId, which did check ownership.

        What the fix was

        The sibling route already had the right guard, which proves the intent. Return 404 (not 403) for someone else's item so item ids cannot be probed.

        Where in codeapps/api/src/routes/cart.ts:~76
        before DELETE removed any item by id
        after 404 unless item.userId === userId
        commit 9194553
        API-5

        Checkout left the cart full

        After paying, the items were still in the cart.

        How it showed up

        After the fix: checkout returns 201, then GET /cart returns an empty list with total 0.

        How we found it

        Followed the checkout route from order creation to its end.

        What the fix was

        The order was created but nothing cleared the user's cart. Add the clear call after the order is saved, not before, so a failed order keeps the cart.

        Where in codeapps/api/src/routes/checkout.ts:~58
        before order saved, cart left full
        after db.cart.clearForUser(userId) after orders.create
        commit 1c26490
        API-6

        Auth was off by default, so cart and checkout crashed

        Cart, favorites and checkout crashed for signed-in users because the server never checked the login token.

        How it showed up

        Without a token /cart now returns 401; with a token it returns 200. Before, the handlers dereferenced a missing user.

        How we found it

        Smoke-testing cart routes: request.user was undefined.

        What the fix was

        Auth enforcement was opt-in (ENFORCE_AUTH had to equal the string true), so by default the verify hook was skipped. A secure default is the correct behaviour: enforce unless ENFORCE_AUTH is explicitly false. This also changed what the web client must send, so it was cross-checked by the web smoke.

        Where in codeapps/api/src/middleware/auth.ts:3
        before enforce only if ENFORCE_AUTH === "true"
        after enforce unless ENFORCE_AUTH === "false"

        WEB-2

        Prices displayed 100 times too high

        A $99 persona showed as $9,900.

        How it showed up

        The card computed persona.price * 100 before formatting. After the fix the smoke run showed normal prices around $49.99.

        How we found it

        Read the persona card component.

        What the fix was

        The API already returns dollars. Multiplying is a unit conversion that does not belong here. Format only.

        Where in codeapps/web/src/components/PersonaCard.tsx:63
        before (persona.price * 100).toFixed(2)
        after persona.price.toFixed(2)
        commit 35175fa
        WEB-3

        Search, filter and sort never refreshed the list

        Choosing a specialty or typing a search did nothing, because the page kept showing the first result.

        How it showed up

        After the fix the smoke run showed the specialty filter changing the list from 15 results to 4.

        How we found it

        Read the browse route's data query.

        What the fix was

        The query cache key was a constant, so every filter hit the same cache entry. The key must include the query string, since TanStack Query refetches when the key changes.

        Where in codeapps/web/src/routes/index.tsx:43
        before queryKey: ["personas"]
        after queryKey: ["personas", queryString]
        commit 0c5ce0a
        WEB-4

        Favorite heart did the opposite

        Clicking the heart on a non-favorite tried to delete it, and clicking a favorite tried to add it again.

        How it showed up

        A stray ! on isFavorited sent DELETE when not favorited and POST when favorited.

        How we found it

        Read the persona page's favorite toggle.

        What the fix was

        One extra negation inverted the condition. Removed it. No other lines needed to change.

        Where in codeapps/web/src/routes/personas/$personaId.tsx:42
        before if (!isFavorited) DELETE else POST
        after if (isFavorited) DELETE else POST (stray ! removed)
        commit 28b1ef3
        WEB-5

        Favorites page and persona page fought over one cache entry

        Opening a persona could corrupt the favorites list, and it asked for favorites while signed out.

        How it showed up

        The same cache key held a list of ids on one page and an object on the other, and there was no signed-in guard (a 401 when signed out).

        How we found it

        Read the favorites queries on both pages side by side.

        What the fix was

        Two different data shapes under one key is a cache collision. Give the ids their own key and only run the query when a user exists.

        Where in codeapps/web/src/routes/personas/$personaId.tsx:23
        before queryKey ["favorites"], no enabled guard
        after queryKey ["favorites","ids"], enabled: !!user
        commit 10f0d2c
        WEB-6

        Logging out did not log you out

        After logout, reloading the page signed you back in, and the next person could see the previous user's cached data.

        How it showed up

        Logout cleared in-memory state only, so the token stayed in localStorage. The smoke run confirms the token is gone and stays gone after reload.

        How we found it

        Read the auth provider's logout function.

        What the fix was

        Auth state lives in three places: React state, localStorage and the query cache. Logout must clear all three.

        Where in codeapps/web/src/lib/auth.tsx:~56
        before logout: setUser(null) only
        after also localStorage.removeItem("auth_token") and queryClient.clear()
        commit 78fdbb0
        WEB-7

        Cart badge never updated

        The number on the cart icon stayed stale after adding or removing items.

        How it showed up

        The badge used the key cart-count, but the mutations invalidate the key cart, so the badge never refetched. The smoke run showed the badge following each change.

        How we found it

        Read the navbar and the cart mutations side by side.

        What the fix was

        TanStack Query invalidates by key prefix. Renaming the key to cart,count makes the existing invalidation reach it, with no new plumbing.

        Where in codeapps/web/src/routes/__root.tsx:16
        before queryKey ["cart-count"]
        after queryKey ["cart","count"]
        commit 70e0caf

        The minus button was styled as disabled but never given the disabled attribute. In the smoke run minus is disabled at 1.

        How we found it

        Where in codeapps/web/src/components/CartItem.tsx:41

        after <button disabled={quantity <= 1}>
        commit 57e54be
        WEB-9

        Star ratings drew the wrong partial fill

        Half stars on one card could show another card's fill.

        How it showed up

        Every partial star used the same SVG gradient id half, so the first gradient in the page won for all cards.

        How we found it

        Read the star rating component.

        What the fix was

        SVG ids are global to the document. Use React's useId so each star gets its own gradient.

        Where in codeapps/web/src/components/StarRating.tsx
        before every star: <linearGradient id="half">
        after id = useId() per star
